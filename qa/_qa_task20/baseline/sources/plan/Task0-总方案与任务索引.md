集合相等的四条可判定口径（R2）：

1. **双向相等**：`deploy/manifest.json` 登记的每一个详情页都必须存在，`Results/` 里也不得存在清单之外的任何文件；多一个少一个都算失败。

### 平铺而非子目录（正向条款）

详情页与列表页一律与壳文件同目录平铺，不使用 `Results/articles/`。理由：子目录会迫使引用改为 `../styles.css`，公共壳随之分裂成两种字节，摧毁"壳外字节全站一致"这条最有价值的不变量，并使本节"所有 href 使用同目录文件名"字面失效。Cloudflare Pages 会把 `/article-x.html` 308 跳到 `/article-x`，根深度平铺使相对引用在跳转前后解析一致；`script.js` 不做路径匹配，故本轮预期零改动。

## 离线 `file://` 全局约束（不可违背）

> **R1 修订（2026-10-01）**：第一版原文把"动态模板或构建产物"与运行期依赖并列禁止（保留作历史描述）。该字面读法会否掉整个归档层——详情页天然是构建产物。现拆为"运行期严禁／生成期允许"两段，原有禁项一条不减，另加一条正向验收。

**运行期严禁**（浏览器打开页面时不得发生任何一条）：

- 所有 `href`／`src` 使用同目录文件名，不以 `/` 开头、不带盘符、反斜杠、查询参数或 URL 片段。
- 不使用 `<base>`，避免改变 `file://` 下的相对路径解析。
- 不引用任何外部资源：无 CDN、无联网字体、无远程图片、无 `http(s)` 请求、无预连接／canonical／Open Graph。
- 不依赖开发服务器、localhost、URL 重写、目录默认页、ES module、`import`、`fetch`、`XMLHttpRequest`、动态模板。
- **运行时读取任何数据文件**一律禁止：JSON／YAML／Markdown 不得被浏览器请求，页面内容必须在构建期就已内联。
- 脚本只用 `<script src="script.js" defer>`；无 `type="module"`、无 `async`、无内联脚本、无内联事件属性、无内联 `<style>` 或 `style="..."`。
- 文件名大小写与各任务登记表完全一致，避免在大小写敏感环境产生仅在 Windows 上不暴露的死链。
- 全部页面（六个壳文件、三个列表页与每一个详情页）均可在无网络、无服务器、直接双击打开的环境下完整呈现与操作。

**生成期允许**（R1）：构建器 `build/build.py` 读取 `content/` 与 `build/`，产出完整静态 HTML 写入 `Results/`。`Results/` 内每一个页面必须是**自包含成品**，其正确性不依赖构建器继续存在——删除 `build/` 与 `content/` 后，页面仍须完整可读、链接仍可点。构建器不得引入任何第三方依赖（仅 Python 3 标准库），不得新增运行时依赖、测试依赖或开发服务器；此处"不新增构建步骤"的第一版表述仅约束**运行期**依赖。

**正向验收**（Task 19 新增回归）：`Results/` 任一页面在**禁用 JavaScript**、**禁用 CSS** 两种情况下仍按正确顺序完整可读、链接仍可点；全站网络请求数为 **0**。

### 日期与排序字段（R5，2026-10-01 新增）

五条均可证伪，任何一条被实现撞穿即判违约：

1. **`date` 只能由用户显式声明**（`YYYY-MM-DD`）。构建器、核验脚本与计划起草者一律**严禁**从 docx 元数据、文件系统时间、正文线索或上下文推断。`date` **只用于排序，永不渲染，永不写入任何输出文件**——包括 HTML 注释、`data-*`、`datetime`、`deploy/manifest.json`、URL 与 slug。判据：`Results/` 任一文件命中 `\d{4}-\d{2}-\d{2}`，或出现字段名字面量 `date`／`display_date`／`end_date`／`order`／`slug`／`column`／`byline`。
2. **`display_date` 必须是本文 `textContent` 的子串**，且匹配 `^\d{1,2}月\d{1,2}日$`。正文里没有的月日一律不得显示；构建器逐项校验，不满足即**拒绝构建**。例：`9月18日` 出现在 `自然选择号9月18日7时电` 之内，故可显示。
3. **全站显示口径不含年份**（沿用电头惯例）。现有三处可显示的月日文本（`自然选择号9月18日7时电`、`自然选择号9月17日电`、页尾 `（自然选择号9月18日）`）都在文章 DOM 文本之内，属 `Task1` 冻结文本。
4. **两个键各管一件事（R9 划分）**：`date` 未声明时该条目排在"未分组"末尾，**只影响次序，不产生任何可见差异**；日期节点的在场性**只由 `display_date` 决定**——缺失时该条目的列表行与首页条目**不生成任何日期节点**（不是空 `<span>`，也不是"日期未知"字样）。判据：缺 `display_date` 的条目其行结构里不存在 `entry-list__date`／`home-latest__date` 元素；带 `display_date` 的条目其排序位置变化不得改变任何输出字节。
5. `end_date`（评论页式结尾行）与 `Task1` 的 `closing_date` 同属**合同内部名**，字面值按 `Task1` 权威文本处理，字段名本身不得出现在 `Results/`。

两个裁决口径由本条一并回答：**"列表页显示日期算不算补日期"**——不算，因为它是正文文本的子串引用；**"不知道年份怎么办"**——照常参与排序（无 `date` 则排未分组末尾）、不显示、不推断，也不得为凑齐次序而代填。
