# Task 18 核验闸门重构

## 后续有效合同补充 R13（2026-10-04）

`manifest.pages` 额外登记 `404.html`；独立集合判据必须将它作为一个固定部署页加入六个现有壳文件与内容源推导的详情页集合，检查项仍须与 zip、磁盘、manifest 双向核对。更新数量公式为 `7 + N`／`8 + N`／`5 + N`，N=6 时为 13／14／11。普通 10 个 HTML 页面继续以 `file://` 生成和绑定快照；`404.html` 是线上专用页，不能混进普通离线快照集合，应在 Task 19 的本地 HTTP 浏览器检查中按自身文件哈希绑定事实。

打包闸门必须能捕获部署包缺少 `404.html`；错误页结构闸门必须能捕获 CSS 或脚本误用相对路径。上述两种故障各保留一个负向对照，确保新增合同确实会翻红。

## 任务定位

本文件把归档总方案中的 Task 18 细化为一个可独立执行、独立验收的工作包。Task 18 交付新的全站只读核验器 `qa/_qa_task18/verify_task18.mjs` 与它的变异对照台 `qa/_qa_task18/mutate_task18.mjs`，接管 `qa/_qa_task10` 在归档层落地后已经失效的那部分职责，并补齐 v1 从未需要的三类判据：**内容源合法性**（`content/` 是否仍是合法的输入）、**页面集合与清单一致性**（`Results/` 是否恰好等于 `deploy/manifest.json` 说的东西）、**保真链**（三篇旧文是否逐字节还是那三篇旧文）。

Task 18 是只读验收包：它不修 `Results/`、不修 `content/`、不修 `build/`、不修 `plan/`。发现问题一律按第一版惯例回流对应上游包，修复后重跑本包。

本包有一条必须先说清的原则：**闸门不能拿被测对象的自我声明当真值**。Task 14 的构建器有自己的 S1–S13 自检，那是"实现者自查"，不是验收。如果 Task 18 直接 `import build.py` 或调用 `build.py --check` 来证明自己正确，就等于让被告当法官——构建器里一个系统性错误（例如把所有 `。` 静默换成 `.`）会同时污染自检与闸门，两边一起绿。因此本包对输入格式**自己实现一份最小独立解析器**，与构建器互不知情的两条链在同一批断言上会师；两处一旦不一致，判 FAIL 而不是取其一。这是本包唯一一处刻意重复的代码，且必须写明理由。

- **变异未捕获且前置断言成立**：真漏检，补断言；**前置不成立**：无效变异，修台架，不改闸门。

## 常见返工风险

- **拿旧快照当新证据**（今天真实发生过）：闸门全绿但比的是九天前的 DOM。M 组就是为此存在。
- **用构建器验证构建器**：`import build.py` 或调 `pack.py verify` 看似省事，实为同义反复；系统性错误会同时通过自检与闸门。
- 把真值手抄进核验器：改了合同忘改编排，于是"页面符合代码、代码不符合同"也能全绿。
- 迁移时以"结构变了"为由删断言，条数悄悄下降而无人追问。
