# Task 4 完成首页内容

## 任务定位

本文件将总方案中的 Task 4 细化为一个可以独立执行、独立验收的工作包。它负责在 `Results/index.html` 已有公共壳中完成《自然选择号》报社简介，只加入“名称由来”“主要工作与报道方向”“成立时间”三个语义区块及其对应的既定占位符。

Task 4 是一次范围严格受限的首页内容填充：不负责撰写报社资料，不负责文章页内容，不负责视觉样式、移动端菜单或脚本交互。完成本任务后，首页应具备稳定、可访问、可供 Task 3 和 Task 8 排版的内容结构，并可由 Task 10 按节点数量、顺序和文本逐项核验。

## 目标

- 保留 Task 2 已冻结的首页公共壳、页面标题和当前导航状态。
- 用三个有标题的 `<section>` 表达三类报社简介信息。
- 将三个已冻结的区块文本一一映射到对应区块，不错位、不改写、不补充事实。
- 为桌面端和移动端样式提供少量、稳定且语义清晰的 class。
- 保证首页除了既定标题、区块标题和三条冻结文本外，不出现新的可见内容。
- 让首页在没有 CSS 或 JavaScript 时仍保持正确的阅读顺序和信息层级。

## 占位符输入合同

### 1. 已冻结的字面值

三个区块文本的权威字面值由用户确认并冻结：`P_ORIGIN`、`P_WORK` 于 2026-09-19 冻结且**至今未变**；`P_FOUNDED` 于 2026-09-30 经用户本人修订（见本节末尾的变更记录）。下表右侧是**必须逐字符照抄的最终网页文本**；`P_ORIGIN`、`P_WORK`、`P_FOUNDED` 只是本计划的引用名，不是网页占位符，不得出现在 `Results/` 中。

| 内部槽位名 | 对应区块 | 权威字面值（含末尾句号，逐字符照抄） |
| --- | --- | --- |
| `P_ORIGIN` | 名称由来 | `我们的名字来自《三体》里的一支舰队。` |
| `P_WORK` | 主要工作与报道方向 | `我们主要记录一些自己觉得有价值的东西。` |
| `P_FOUNDED` | 成立时间 | `报社成立于“鸽子衔枝之年”。` |

字面形式的明确约定：

- 三条都是完整单句，**以中文句号 `。` 结尾**；该句号属于冻结文本，实施者不得删除，也不得再自行追加其他标点。
- `P_ORIGIN` 中的书名号 `《三体》` 需要显示；三条整句都不被引号包围，但 `P_FOUNDED` 内含一对全角引号 `“鸽子衔枝之年”`，该引号属于冻结文本本身，不得删去、不得换成半角引号或其他引号形态。
- `P_FOUNDED` **不含任何阿拉伯数字**：成立时间以“鸽子衔枝之年”这一表述给出，不写公元年份、不写月份、不写具体日期、不追加“至今”。
- 三条文本都不含半角空格。
- 本版（2026-09-30）之前该句为 `报社成立于2024年。`。`2024` 是用户 2026-09-19 明确提供的报社事实，现由用户本人于 2026-09-30 替换为上式——这是一次**经作者批准的内容变更，不是漂移**。后果有两条：全站首页不再出现任何四位数字，`Task10`／`Task18` 的四位数字扫描因此不再需要 `2024` 豁免；禁止项里“由 Word 文件时间推断的 `2026`”继续有效，且今后若重新引入任何公元年份，必须先修订本节而不得由实现者自行补上。
- 内容含义不得再被改写：名称由来只说“来自《三体》的一支舰队”，不展开舰队编制或情节；主要工作只说“记录自己觉得有价值的东西”，不补报道领域、栏目或频率；成立时间只到年份。

Task 3 的“建议结构”中出现过一个用于说明样式效果的方括号示例，那不是首页内容合同。上表的三条字符串是唯一可以进入最终 HTML 的首页区块文本。

### 2. 实施前确认要求（已完成）

三条字符串已按下表逐项确认完毕，实施 Task 4 时直接采用上节的冻结值，不再重新征询或改写：

1. 每条字符串对应哪个区块——已按“名称由来／主要工作与报道方向／成立时间”一一映射。
2. 全部汉字、数字、英文、标点、括号和空格的字面形式——已冻结；三条均无半角空格，`P_ORIGIN` 含书名号 `《》`，三条均以 `。` 结尾。
3. 字符串是否包含本身需要显示的书名号、引号或其他包围符号——仅 `《三体》` 的书名号需要显示。
4. 字符串中是否有必须保留的半角空格——三条都不含半角空格，实施时不得为视觉效果添加。
5. 三条字符串是否都只是占位文本，而不是要求根据常识扩写的提示——不是扩写提示，是最终成稿文本，直接照抄。
6. 每条字符串都是非空、非纯空白且不包含 CR 或 LF 的单段文本——均满足。

不得用“暂无资料”“待补充”“成立时间未知”等自行拟定文字替代冻结值，也不得从 Word 文件属性、文件创建时间、新闻日期、站点名称或文章内容推断报社事实。若用户此后提供更动版本，必须先更新本节与上节的冻结表，再改 HTML；不得只改页面而让合同滞后。

### 3. 文本保真规则

- 每个占位符完整放入对应区块的一个 `<p>` 中。
- 空字符串、纯空白字符串或带换行符的字符串不符合当前单段结构合同；遇到此类权威值时必须暂停并确认是否调整结构。
- `<p>` 内只放该占位符的纯文本，不添加“名称由来：”“答：”“简介：”等前缀。
- 不纠错、不润色、不换同义词、不补句号、不统一全半角标点。
- 不将一个占位符拆成多个段落、列表项、链接或强调元素。
- 不使用 `<br>` 人工断行，不插入 `&nbsp;` 调整版面。
- 若文本包含 HTML 保留字符，应在源代码中正确转义，但浏览器取得的 `textContent` 必须与确认值逐字符相等。
- 为避免缩进换行进入文本核验，最终 `<p>` 的开始标签、文本和结束标签应写在同一行。

## 语义与无障碍合同

- 页面仍只有一个 `<main>` 和一个 `<h1>`。
- 三个简介区块各使用一个 `<section>`，不能用三个无语义的通用容器代替。
- 三个区块标题都使用 `<h2>`，形成 `h1 → h2` 的连续标题层级；不得使用 `<h3>`、加粗段落或纯视觉大字代替。
- 每个 `<section>` 的 `aria-labelledby` 必须精确指向本区块唯一的 `<h2 id>`。
- 三个标题 ID 在页面内各出现一次，不得与公共壳中的 ID 重复。
- 阅读顺序必须是主标题、名称由来及其文本、主要工作与报道方向及其文本、成立时间及其文本。
- 占位符即使很短也必须放在段落中，不能放入 `aria-label`、`title` 属性、注释、`data-*` 属性或仅供屏幕阅读器使用的隐藏节点。
- 不对静态简介使用 `<article>`、`<aside>`、`<details>`、选项卡、折叠面板或 ARIA widget role。
- 不为标题添加冗余 `aria-label`；可见 `<h2>` 已提供区块名称。
