## 7. 闸门比 v1 强在哪、弱在哪

**强在六处：**

1. **结论可归属**。M 组把每条 DOM 事实钉在来源文件哈希上；v1 会拿九天前的快照当"实际值"报假红（本包表19 变异证明这条现在必红）。
2. **不再自证**。Q 组另实现一份 `content/` 解析器、N 组自行解压 zip，都不调用 `build.py`／`pack.py verify`；构建器的系统性错误不会再同时污染自检与闸门。
3. **判据面从"页面"扩到"链路"**。多出 L（保真三腿）、M（快照绑定）、Q（内容源合法性）、P（链接图）、N（打包形态）五组共 367 条，占本包 32%；v1 完全没有这一层。
4. **真值锚点化**。段落数、命名正则、白名单、年份形态、接口类名、素材哈希一律解析而非常量；`anchor_spotcheck.py` 十条改动即随动。
5. **崩溃不再冒充结论**。结构破坏记"区块缺失 FAIL"；锚点缺失记 `[GATE-ANCHOR]` 并拒出结论；退出码 0／1／2 严格分开且崩溃计为 FAIL。
6. **豁免面为零**。全站年份形态扫描 `(19|20)\d{2}` 命中 0，代码层与行为层（三条 canary）双向自检；白名单不存在"条件版本"。

**弱在六处（如实登记，不当已解决）：**

1. **不做视觉断言**。视口／缩放／交互／降级／像素配色全部移交 Task 19；本包因此**不能**独立发现"布局错但文本对"的缺陷。
2. **Task16 第 9 类（44px 触控下限）本包无等价像素判据**。该变异由 `A1b/sha/styles.css`（R10 唯一写入者字节守卫）接住，能发现"改了样式表"，但不能判断"改完之后点击区是否仍 ≥44px"。
3. **`H4` 不再拿 `Task0 §样式变量` 当穷举注册表**（该节是散文摘要，未点名的 `--line-height-*` 等是 Task 3 既有交付）。改由"首个 `:root` 完备性 ＋ 对 `_qa_task16/before_styles.css` 零新增变量"两条可判据替代——覆盖面比 v1 的写死字典更严，但变量语义等价性仍不可判。
4. **快照仍是"某一轮"的**。M 组能证明快照与被测目录一致，不能证明该快照是在"业务上正确的那一刻"取的；每改一篇 `content/` 并跑完构建后必须重跑 `probe_task18.mjs`，否则 M1 红。
5. **`A5`／`R0` 只读证明是"轮内"守卫**：它比较的是同一次核验开始与结束的五处目录哈希，因此能抓"闸门自己写文件"，不能替代 `A1b`（对清单）跨轮发现交付物漂移。
6. **依赖锚点文本的稳定性**。锚点是 markdown 字面量，合同改写措辞（不只是改值）可能让解析器判"锚点缺失"——本包选择"拒绝出结论"而不是猜，代价是需要上游同步（见下节）。
