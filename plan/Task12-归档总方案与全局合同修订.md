## 任务定位

本文件把《历史文章系统》的总方案细化为一个可独立执行、独立验收的工作包。Task 12 是归档层的**第一个工作包，也是唯一不产生任何交付文件的工作包**：它只修改和新建 `plan/` 下的合同，把"栏目页变列表页、一篇文章一个详情页、Markdown 源文件加构建脚本"这一新结构所必须依赖的规则，先写进全局方案与首页内容合同，再据此起草 Task 13–Task 19 六份执行合同。

Task 12 的存在理由是一个事实：第一版合同在字面上**禁止**归档层所必需的东西。`plan/Task0-总方案与任务索引.md` 的"离线 `file://` 全局约束"明文写着不依赖"动态模板或构建产物"，"交付集合（固定六文件）"明文写着 `Results/` 不得出现第七个文件；核验器 `qa/_qa_task10/verify_task10.mjs` 第 133 行断言文件数为 6、第 213-216 行的 **C6**（标签"公共壳节点数量"）断言每页恰好一个 `<nav>`、首页 `<main>` 内的标签计数被锁成 `{main:1,h1:1,div:1,section:3,h2:3,p:3}`。如果不先修订这些条款，Task 15 落地的那一刻就会同时违反五条既有合同，而按第一版的裁决顺序，那属于"在下游私自兼容两个版本"的禁止行为。

因此 Task 12 的产物不是代码，而是**七条经用户批准的合同修订（R1–R7）**、执行期按阻断规则二追加的四条（R8–R11），外加七份新计划文件。Task 12 不得借此机会重新解释任何已冻结文本，不得改动 `Results/`、`Materials/`、`content/`、`build/`、`deploy/` 下的任何文件。

## 常见返工风险

- 把 R2 写成"`Results/` 可以有任意文件"，丢掉"集合双向相等"与"数据文件仍禁止"，于是 JSON 或 Markdown 混进部署根而无人报警。
- 让首页最新区用 `<nav>`，撞穿 C6 的 `nav === 1`，再顺手把 C6 改窄，144 条壳基线的可信度打折。
- 让新块复用 `.home-section` 类，E3 的 `.home-section` 计数从 3 变 4，等于偷偷改掉了首页冻结结构。
- 在 `Task4` 修订时顺手"润色"三段文本或调整标点，破坏 `E6` 的逐字符合同。
- 把 `date` 写进 HTML 注释、`data-*`、`manifest.json` 或 slug，认为"反正看不见"；年份照样从 URL 与属性泄漏出去。
- 让 `display_date` 变成可自由填写的字段，于是列表页出现正文里没有的日期——与"不补日期"总则正面冲突，且无法被核验。
- 误以为"四位数字扫描需要 `2024` 豁免"而把豁免写死进闸门：R7 之后首页已无四位数字，保留一条永不命中的豁免等于给未来重新塞进年份留了后门。豁免面应当只有 `Task1` 冻结正文里的月日与两位／一位数字。
- 在 `plan/` 里为了举例写下 `新闻评价`、`厨一枚`、素材哈希，然后被扫描范围误配（扫描只针对 `Results/`），或者更糟：被复制进交付页。
- 把 `build/shell.html` 直接当页面放进 `Results/`，让 `{{TITLE}}`、`{{MAIN}}` 槽位记号出现在公开页面上。
- 只在 `Task0` 登记新类却忘了同步 Task 16 合同，或反之，导致"未注册 class"断言在闸门重构后无人认领。
- 把 `manifest.json` 视为交付文件放进 `Results/`，破坏 R2 第 4 条并被 A2 判违规。
- 让 Task 13 直接改 `Results/` 以"对齐字段"，摧毁迁移前基线，令保真证明失去参照。
- 在计划里规定排序"按日期倒序"却不定义同日期与缺日期的破序规则，构建顺序随之不稳定，回归无法判定。
- 用 `date` 之外的隐式次序（文件名、mtime、`Object.keys`）排序，换机即换序。
- 起草六份下游合同时写成"由实现者判断"，把裁决推给下游，正是第一版明令禁止的做法。
