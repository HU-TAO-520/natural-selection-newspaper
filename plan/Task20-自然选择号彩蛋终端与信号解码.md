## 0. 给执行者的入口

本任务在现有静态报纸站中增加一个《三体》书迷彩蛋，暂名“自然选择号：最后的回波”。入口是首页原有的“鸽子衔枝之年”；玩家进入舰桥档案终端，依次完成命令译码、航迹归档、信号对齐，复原章北海与“自然选择”号从脱离航行到黑暗战役的记录。

实施顺序固定为：**现场基线 → 合同修订 → 静态叙事 → 游戏核心 → 界面绑定 → 样式 → 主站接入 → 预览目标 → 双目标打包 → 核验迁移 → 浏览器验收 → 本地回归 → 维护交接 → 发布交接**。具体执行步骤见第 10 节。每一步都给出输入、可写范围、操作和退出标准；上一步未通过时，只修复该步，不提前改下游来制造通过结果。

执行时优先记住以下约束：

1. 同一套游戏源生成主站彩蛋页与子域名首页，游戏规则和叙事不得出现两个版本。
2. 首页原文和六篇文章不改。首页仅允许为指定词组添加一个链接包装；共享导航脚本保持原哈希。
3. 原报纸页面、主站 404、彩蛋页面、彩蛋预览 404 分别有结构合同；全部仍接受文件集合、链接、资源、内容泄漏和打包检查。
4. 所有游戏资料随静态 HTML/JS 交付。浏览器不读取 Markdown/JSON，不访问 API，不依赖服务器来计算答案。
5. 主站包与彩蛋预览包分别生成、分别核验。前者上传到生产环境，后者上传到同一 Pages 项目的 easteregg 预览分支。
6. 核验失败须记录原因与对应合同；不得删除断言、替换历史基线、扩大任意文件白名单或重写报告来消除失败。

- 主站首页文字仍逐字符一致；只新增一个明确登记的词组链接，鼠标、键盘和触摸均可进入。

## 6. 三幕规则与交互合同

### 6.1 第一幕：脱离／命令译码

规则：ASCII 大写字母统一向前编码三位，解码时向后移动所选校准值；字母循环，非字母原样保留。固定已知明文为 ZIRANXUANZE，密文为 CLUDQAXDQCH；指令密文为 TLDQMLQVL，正确解码得到 QIANJINSI。不要改成随机位移或为中文汉字实现额外密码。

界面包括两行已知呼号、指令密文、0—25 的原生 range 校准控件、即时译码输出、指令输入框和“校验指令”。初始校准=0、答案为空。呼号明文的标签为“自然选择／固定呼号”，并提示“呼号与指令均用无声调大写拼音”。

成功必须同时满足校准=3、答案归一化后为“前进四”或“前进4”。归一化仅做 Unicode NFKC、移除空白；不采用模糊匹配，不接受仅填写“章北海”“QIANJINSI”或其他近似指令。

| 输入情形 | 结果 |
| --- | --- |
| 值 3 + 前进四/前进4 | 第一幕恢复，显示 P11—P13，提交控件禁用 |
| 答案正确，但值不是 3 | 不通过；“载波尚未校准，先核对固定呼号。” |
| 值 3，但答案为空 | 不通过；“请输入恢复出的推进指令。” |
| 值 3，但答案错误 | 不通过；“拼音已恢复，指令与记录不符。” |
| 切换校准值 | 只更新译码及本幕草稿，不自动提交或跳幕 |
| 重复提交已通过的本幕 | 幂等；不重复追加段落，不创建新计时器 |

### 6.4 提示与回放的共同规则

每幕提示按钮最多展开三级。前两次只展示新提示，不改变谜题结果；第三次展示答案和一个独立的“直接复原本段”按钮，必须再次点击才代为填写并提交。允许书迷完全凭记忆解题，不强制打开提示。

未开始或未开放的幕不能请求提示；已完成的幕可阅读已有提示，但不再改变状态。提示无倒计时和惩罚。直接复原走同一正确解法校验，不设置一个绕过前置状态的 unlockAll 开关。

“重新回放”清除本彩蛋会话进度并回到开场；不清空整个 sessionStorage，不刷新其他页面，不影响报纸导航。返回报社是正常链接；点击后不弹出确认，当前会话的进度保持。

## 7. 状态、存储与渐进增强

### 7.1 核心接口

core.js 包含与 DOM 无关的函数：decodeCaesar、normaliseAnswer、checkDeparture、checkRoutes、checkSignals、initialState、reduce、restore。代码在浏览器作为经典脚本运行；Node 环境有 module.exports 时导出这些函数供规则检查，UI 部分以 document 是否存在作启动守卫。浏览器不使用 import、ES module、动态代码执行或网络读取。

reduce(currentState, action) 返回下一状态，不修改传入对象；未知 action、越幕 action 或越界值保持原状态。事实判定独立于动画完成、节点文本和 CSS 类；UI 仅反映状态。不存在通过比较“按钮上显示了恢复”来推断已经成功的逻辑。

### 7.2 会话数据

存储键固定为 ns-bridge-v1。以下为版本 1 的字段合同，数据只存于当前浏览器会话，不加入部署清单或网页中的 data-* 属性。

~~~json
{
  "version": 1,
  "stage": 0,
  "cleared": [false, false, false],
  "shift": 0,
  "answer": "",
  "routes": {"natural":"", "blue":"", "enterprise":"", "deep":"", "ultimate":"", "quantum":"", "bronze":""},
  "offsets": [0, 0, 0],
  "hints": [0, 0, 0],
  "assisted": [false, false, false]
}
~~~

stage=0 是开场，1/2/3 是当前幕，4 是终幕。第一幕通过仍留在 stage=1 展示恢复段落；“继续复原”才进入 2。第二幕同理。第三幕通过直接进入 4。

cleared 必须是连续前缀：不得存在 [false,true,false]。stage=2 要求第一幕已通过，3 要求前两幕已通过，4 要求三幕全部通过。每个 true 还必须能从对应保存的解法重新验证；不能仅信任缓存中的 cleared 标志。已解题控件禁用，因此正常状态下草稿不会在通过后变为错误答案。

stage/cleared 的合法组合精确为：0→000，1→000 或 100，2→100 或 110，3→110，4→111。其中 0/1 表示 false/true。其他组合即使是连续前缀也无效，例如 stage=0 且 cleared=111；恢复时不得因此开放未来章节。

输入范围：shift 为 0—25 的整数；offsets 三个 -3—3 整数；hints 三个 0—3 整数；routes 仅七个指定 key，值为 ""/"A"/"B"；answer 为字符串且最多 64 个字符；布尔数组长度恰为三。version 不匹配、非 JSON、字段缺失、未知 route 或不可能的进度均整体恢复为 initialState，不尝试猜测性迁移。

存储调用均包 try/catch。读取或写入受限时游戏继续以内存状态运行；不每次弹警告，不生成控制台异常。刷新续玩承诺适用于支持 sessionStorage 的同源同标签环境；file:// 被浏览器限制时，内存降级是合法结果。主站和预览子域名属于不同源，不同步进度；新标签也不承诺与已有标签实时共享。

### 7.3 Action 及转移

| Action | 允许状态 | 行为 |
| --- | --- | --- |
| START | stage=0 | 开放第一幕 |
| SET_SHIFT / SET_ANSWER | 未完成的第一幕 | 保存局部草稿 |
| SET_ROUTE | 未完成的第二幕 | 更新一艘的归属 |
| SET_OFFSET | 未完成的第三幕 | 更新一条记录的偏移 |
| SUBMIT | 当前未完成幕 | 正确则设置相应 cleared，错误保持草稿与当前幕 |
| CONTINUE | 第 1/2 幕已通过 | 前进一幕 |
| HINT | 当前未完成幕 | 当前 hints 增一，最大为 3 |
| APPLY_HINT | 当前未完成幕且提示达到 3 | 填正确数据后走正常 SUBMIT，标记 assisted |
| REPLAY | 已启动或已完成 | 返回 initialState，仅清除本彩蛋键 |

完成状态、解法与提示在每次有效动作后写入会话；REPLAY 是例外，仅 removeItem 本彩蛋键，不立即把 initialState 写回，下一次 START 后再正常保存。使用事件委托或一次性绑定，重绘和续玩不得重复注册监听器。每次提交结果在一个 role=status/aria-live=polite 区域简短反馈，完整新档案正文不整段强制朗读。

### 7.4 HTML 与无障碍最低接口

页面根节点保留 no-js 初值；唯一 main 使用 id=main-content 并接受程序焦点；跳至正文链接指向它。全页唯一 h1 是游戏标题。彩蛋没有纸媒四项菜单，也不加载 script.js。

必须存在的 ID：egg-start、egg-status、egg-stage-one、egg-stage-two、egg-stage-three、egg-shift、egg-code、egg-answer、egg-departure-check、egg-routes-check、egg-offset-telemetry、egg-offset-weapons、egg-offset-voice、egg-signals-check、egg-ending、egg-replay、egg-return、egg-archive、egg-feedback。其余本轮新增 ID/class 统一以 egg- 开头并在接口报告列出；主站入口类例外为 home-easteregg-link。

七个航迹 select 使用 egg-route-<key>，每个都有可见舰名 label。所有 range 都有可见 label、当前值 output 及文字同步状态。触控和键盘都通过原生控件操作；不能用鼠标拖动模拟滑块代替原生 range。

提交指令采用 form 的 submit 事件并 preventDefault；按钮没有内联处理器。回车只提交一次。成功后焦点移到新恢复段落的标题，继续按钮在其后；进入下一幕时焦点移到下一幕标题。重放回到开场按钮。返回链接始终可见，不把玩家锁进全屏或焦点陷阱。

### 7.5 无 JS、无 CSS 与启动失败

terminal.html 本身按顺序包含 P00—P35 和三幕档案，可直接阅读。JS 专用控件初始带 hidden，档案初始可见。成功完成绑定与初次状态渲染后，才切换 no-js→js、开放控件并隐藏尚未解开的档案。未来档案用真实 hidden 属性隐藏，不能仅降低 opacity 或移出画面而仍被读屏读到。

禁 JS 时控件保持隐藏、完整档案可读，显示“可直接阅读完整复原档案”。CSS 被禁用时，JS 的状态和原生控件仍正确工作，文档顺序和 label 保持可读。若初始化失败，恢复静态档案和返回入口，控件保持隐藏，不停留在空白或永远加载的状态。存储异常只触发内存模式，不属于初始化失败；分别用存储访问抛错和 QA 副本中的一次非存储初始化异常，验证这两条降级路径，不向正式源保留故障开关。

### 11.1 QA 输出和退出码

qa/_qa_task20/ 的新检查至少包含下列入口；内部函数可以合理拆分，不增加生产依赖。

| T20-O02 | 两域名 CSS/JS、主站原 script/styles 与对应清单 | SHA-256 一致，资源未被服务端改写 |
| T20-O03 | 主站入口往返、预览返回报社、后缀重定向 | 相对资源和入口不被重定向破坏 |
| T20-O04 | 两域名未知单层/嵌套路径与安全头 | 404、原地址保留、对应错误页身份与 CSS 正确 |

HTTP fixture 仅是 QA 工具，写在 qa/_qa_task20/，监听 Loopback、临时端口；分别服务主站/预览两个真实产物目录。读取实际 _headers 设置响应头，不用 iframe 包装页面，未知路径以相应 404 成品返回且状态码=404。它不进入 Results 或 ZIP，也不成为游戏运行条件。

网络验收的精确定义：file:// 游戏不产生 HTTP(S) 请求；HTTP 游戏只加载当前目标同源 HTML/CSS/JS。用户主动点击“返回报社”产生的导航不算违规联网解谜。浏览器自身的失败 favicon 探测不能伪装成生产资源正常：fixture 对它与页面自发请求分别记录，页面不添加新的 favicon 文件来改变交付集合。

截图至少包括：桌面/手机首页入口，手机第一幕，桌面第二幕，手机第三幕，桌面/手机终幕，以及 200% 缩放代表页。必须人工看图核对文字截断、段落节奏、控件和阅读顺序；DOM 几何通过不等于视觉已经合格。试玩记录实际解题时间与是否使用提示，5—8 分钟是体验目标，不是强制合格时间窗。

## 12. 异常处理与返工边界

| 现象 | 先查什么 | 处理 |
| --- | --- | --- |
| 包装链接后构建失败 | load_partial、golden 冻结区、HOME_TAG_COUNTS | 只做指定包装逆变换及 R14 计数，不替换历史基线 |
| 彩蛋在 Task18/19 被判缺导航 | 角色分区与检查接管 | 修遍历集合，保留全站资源/文件/安全覆盖 |
| 预览清单被判零文章非法 | pack profile 与主站 content 校验是否串用 | preview articles=0 合法；主站每栏至少一篇继续有效 |
| HTML 数和页面数不一致 | 两目标资源数、404 是否在清单 | main 减四资源；preview 减二；不混用三个数字 |
| JS/CSS 被 CSP 拦截 | inline/style 属性、资源根路径、生成脚本类型 | 改为经典外部脚本与类切换，不放宽 _headers |
| 波形视觉移动但不能通关 | 实际 state、样式映射、目标中心 | 规则以固定采样位置判定，修 UI 与状态映射 |
| 未来正文能被读屏访问 | 是否只用 opacity/position 隐藏 | 用 hidden 正确管理可见性，静态降级仍可读 |
| 刷新直接显示结尾 | restore 是否校验连续进度与实际解法 | 无效缓存清本彩蛋键并回开场，不能信任布尔数组 |
| main/preview 文案分叉 | 是否复制两套 template 或在 UI 按域名分派 | 回到同一源，只保留规定 URL 差异 |
| CDP/Chrome 启动失败 | 端口、独立 profile、工具路径及安全限制 | 记录环境异常，保留已完成产物，不伪造浏览器通过 |
| 有清单外陌生文件 | 来源是否本轮受控产物 | 只报告；不代为删除未知文件，也不悄悄打包进去 |
| 实施过程中用户加稿 | 新稿是否经用户授权及当前 N | 先核实变更，更新受影响的开工记录/计数，不覆盖新稿 |
| 域名是旧内容/200 回退首页 | title/h1、资源哈希、环境标签 | 按实际身份判失败，核对上传目标，不只看 HTTP 200 |
| 尚未上传/未提供账户操作 | 本地验收是否已完成 | 完成本地交付，准确写待发布；不建立无请求的自动监控 |

返工从故障所属步骤开始，影响到的下游重新验证；不退回重写整个报纸系统。发生真实写盘错误时，保留现场与快照，在已授权范围中恢复本轮受控文件；不对陌生文件做删除/搬移。不使用“因为模型较小”作为略过核验、猜测原著或降低合同的理由。
