# Task 11 浏览器回归与集成验收

## 任务定位

本文件将总方案中的 Task 11 细化为一个可以独立执行、独立验收的工作包。它负责在真实浏览器中，对 `Results/` 已完成的六个交付文件做端到端回归：从 `file://` 直接打开四页，在桌面与移动断点、浏览器缩放、键盘操作、菜单交互、禁用 JavaScript／CSS 降级以及控制台与网络层面，确认整站的可读性、可操作性、可访问性与视觉一致性符合 Task 1–Task 9 的合同。

Task 11 是全流程的最后一道闸门，也是唯一以“真实运行时行为”为对象的验收。Task 10 已经用确定性断言核验了结构、逐字符文本、哈希与静态模式；Task 11 不重复这些静态判定，而是验证只有浏览器实际渲染与交互才能暴露的问题：版心与溢出、字号与换行、焦点可见性、点击区尺寸、菜单三态、跨断点状态重置、降级表现、控制台报错与资源加载。

Task 11 是只读验收任务。它不录入内容、不写视觉、不改交互、不修复缺陷。发现问题只记录复现步骤并回流对应上游任务；修复后重跑相关 Task 10 断言与 Task 11 回归。核验过程中产生的截图、控制台脚本、测量记录都是临时 QA 产物，绝不落入 `Results/`。

## 目标

- 从 `Results/index.html` 起，用真实浏览器覆盖四页，不以某一页通过推断其他页通过。
- 在 375px、768px、769px、1280px 四个固定宽度和 200% 浏览器缩放下完成四页回归，确认布局按断点合同切换。
- 严格以 `scrollWidth <= innerWidth` 判定横向溢出，不额外放宽 1px。
- 验证菜单三种视觉状态（`.no-js` 常显、`.js` 关闭、`.js .is-open` 打开）与 Task 9 的交互行为（点击、Enter／Space、Esc、焦点返回、链接关闭、跨断点重置）。
- 验证按钮与每个导航链接的实际点击区不小于 44×44 CSS px，焦点轮廓清晰且不被裁切。
- 验证禁用 JavaScript 时导航常显可访问、禁用 CSS 时阅读顺序完整。
- 确认四页在全部操作过程中控制台 0 错误、0 警告，`styles.css` 与 `script.js` 无 404、无外部网络请求。
- 确认桌面视觉未被移动规则污染、移动视觉未破坏桌面基线，纸媒风格与正文保真在浏览器中一致。
- 产出可追溯到断言编号的回归结论；任何失败附复现步骤与应移交的上游任务。

## 验收环境与工具

- 环境：本地 `file://` 直接打开，不启动开发服务器、不联网、不依赖 URL 重写或目录默认页。
- 推荐工具：可用的浏览器自动化（如 browser-use：`navigate_page`、`take_snapshot`、`evaluate_script`、`click`、`press_key`、`take_screenshot`、`list_console_messages`、`list_network_requests`）或等价的真实浏览器加开发者工具。
- 几何测量：用一次性 `evaluate_script` 读取 `window.innerWidth`、`document.documentElement.scrollWidth`、元素 `getBoundingClientRect()`；脚本只读，不改 DOM，不保存回文件。
- 缩放协议（与 Task 8 一致）：先在 100% 缩放下把浏览器内容区设为 `window.innerWidth === 1280`，再把浏览器真实缩放调到 200%，硬刷新并记录新的 `window.innerWidth`；随后按实际 CSS 视口判定，不用 CSS `zoom`、`transform: scale()` 或截图放大模拟真实缩放。
- 降级测试：禁用 JavaScript 必须“先禁用再硬刷新”，确保源码 `html.no-js` 生效；只在脚本运行后临时关闭 JS 不能证明降级正确（DOM 可能仍残留 `html.js`）。

## 验收断言清单

每条断言都应在回归报告中以编号记录通过／失败。失败项必须附：所在页面、复现宽度或状态、操作步骤、期望 vs 实际、应移交的上游任务。

### R-A 加载与资源

- **RA1** 四页均可从 `file://` 直接打开，无加载级错误。
- **RA2** 网络面板中 `styles.css`、`script.js` 均成功加载（非 404）；无任何外部 `http(s)` 请求、无远程字体、无 CDN。
- **RA3** 全部操作过程中控制台 0 错误、0 警告（含脚本自身输出）。
- **RA4** 无因路径解析导致的资源缺失或死链；16 条主导航路径点击后都能到达现有页面。

### R-B 桌面视觉（769px／1280px，四页）

- **RB1** 1280px 下公共版心宽度不超过 1120px，左右留白对称；1024px（如测）下版心约 960px。
- **RB2** 文章正文宽度不超过 736px；首页文字区不超过 736px。
- **RB3** 报头“自然选择号”完整显示，双细线不被文字穿越；四项导航同一行、顺序正确、无重叠。
- **RB4** 汉堡按钮在桌面隐藏；主导航横向常显。
- **RB5** 当前页链接为暗红、较粗并带下边框；普通链接为深色；悬停不缩放或移动链接。
- **RB6** 颜色、字体（宋体栈，回退 `serif` 仍可读）、分隔线与 Task 3 变量一致；无渐变、阴影、卡片圆角、分栏等被禁视觉。
- **RB7** 桌面 `scrollWidth <= innerWidth`，无水平滚动条。

### R-C 移动视觉（375px／768px，四页）

- **RC1** 左右留白各约 16px；版心随可用宽度收缩，无固定内容宽度、无内部滚动区、无裁切。
- **RC2** 报头与页面标题按 `clamp()` 流式缩小：375px 下明显变小但仍比正文醒目，长评论标题自然换成多行、无单字孤悬、不溢出。
- **RC3** 首页三区块保持单列、顺序与分隔线不变；不变成卡片、轮播、折叠面板。
- **RC4** 三篇文章保持单栏、`2em` 首行缩进、正常文档流；`.dateline` 仍内联；`.article__date` 仍右对齐、无首行缩进、极窄宽度下可自然换行不溢出。
- **RC5** 中英文混排与技术术语（`AI`、`.exe`、`Windows 10`、`UOS`、`USB`、`OPS`、`Linux`、`4K`）正常换行，未被 `word-break: break-all` 打断，未插入 `<wbr>`／软连字符，原文字符不变。
- **RC6** 移动 `scrollWidth <= innerWidth`，无横向溢出（严格判定，不放宽 1px）。
- **RC7** 移动端正文两端对齐已改为 `text-align: start`，窄行中英文混排无过大字间空隙。

### R-D 点击区与焦点（移动，四页）

- **RD1** `.nav-toggle` 的实际 `getBoundingClientRect()` 宽与高均 `>= 44` CSS px。
- **RD2** 每个可见 `.site-navigation__link` 的实际宽与高均 `>= 44` CSS px；链接占满行宽便于触控。
- **RD3** 通用 `:focus-visible` 轮廓（暗红实线）在按钮与导航链接上清晰可见，不被边框、展开菜单或容器裁切。
- **RD4** 跳转链接 `.skip-link` 是第一个 Tab 停靠点；首次 Tab 后出现在左上角、文字与背景清晰；激活后跳到 `#main-content` 且正文区域获得可感知焦点，不推动报头、不产生横向滚动。

### R-E 菜单三态（移动，四页）

- **RE1（`.no-js` 常显）** 禁用 JS 硬刷新后：按钮不可见且不在 Tab 顺序；四项导航纵向、完整可见、可点击、可聚焦；当前页以颜色与线条区分；焦点轮廓不被裁切。
- **RE2（`.js` 关闭）** JS 可用硬刷新后：按钮可见、`aria-expanded="false"`、导航无 `.is-open` 且视觉折叠（`display:none`）；四个隐藏链接不出现在 Tab 顺序；页面不因隐藏导航留下异常固定高度或空白。
- **RE3（`.js .is-open` 打开）** 激活按钮后：导航获得 `.is-open`、`aria-expanded="true"`；四项纵向完整显示、点击区均 `>=44×44`；展开菜单不覆盖、不截断、不横向推挤报头与正文；Tab 顺序自然。
- **RE4** `.is-open` 与 `aria-expanded` 永不脱节；不存在只改其一的状态。

### R-F 交互行为（Task 9，四页）

- **RF1** 点击按钮切换开／关各一次，状态与 ARIA 同步。
- **RF2** 聚焦按钮按 Enter／Space 等效触发一次切换，无双触发。
- **RF3** 打开态按 Esc 关闭菜单并把焦点返回按钮；关闭态按 Esc 无副作用（不抢焦点、不滚动）。
- **RF4** 打开态点击任一导航链接关闭菜单，随后正常导航；同页链接与当前页链接也不残留展开状态。
- **RF5** 采用披露式（非模态）焦点策略：打开后焦点不强制移入菜单，保持在按钮，Tab 自然进入链接。
- **RF6** 脚本未用 `tabindex`／`aria-hidden`／`hidden` 管理链接可聚焦性（折叠由 CSS `display:none` 负责）。
- **RF7** 打开菜单后点击菜单外区域（正文、报头等），菜单**保持展开**——这是用户已确认的合同行为（不实现点击外部关闭），不得据此判失败；关闭只经按钮再次激活、Esc、点击导航链接或跨到 ≥769px 发生。

### R-G 跨断点重置（四页）

- **RG1** 在 768px 打开菜单后拉宽到 769px：按钮隐藏、四项导航横向可见、移动 `display:none` 不再生效、`.is-open` 已清除、`aria-expanded` 重置为 `false`。

## 执行步骤

1. **确认入场前提**：核对 Task 10 已判定通过、无未决 `FAIL`；六个文件存在且非空壳。任一不满足则停止，回流对应任务。
2. **冻结只读基线**：记录回归开始前 `Results/` 六个文件的 SHA-256 与文件清单，作为“回归未改动交付物”的对照。
3. **加载与资源（R-A）**：逐页 `file://` 打开，检查控制台与网络面板，确认 0 报错、资源无 404、无外部请求。
4. **桌面视觉（R-B）**：在 769px、1280px（及需要时 1024px）逐页检查版心、正文宽度、报头、导航、当前页、焦点与横向溢出。
5. **移动视觉（R-C）**：在 375px、768px 逐页检查留白、流式字号、首页三区块、文章单栏与首行缩进、技术术语换行、横向溢出。
6. **点击区与焦点（R-D）**：在移动宽度用几何测量确认按钮与链接 `>=44×44`，检查焦点轮廓与跳转链接。
7. **菜单三态（R-E）**：分别构造 `.no-js`（禁用 JS 硬刷新）、`.js` 关闭、`.js .is-open` 打开，逐页验证显示、Tab 顺序与状态同步。
8. **交互行为（R-F）**：逐页执行点击、Enter／Space、Esc＋焦点返回、链接点击关闭，确认无双触发、无脱节。
9. **跨断点重置（R-G）**：768px 打开→拉宽到 769px→再缩回，确认状态清理与桌面恢复。
10. **缩放回归（R-H）**：按缩放协议从 1280px／100% 切到 200%，记录前后 `innerWidth`，按实际视口复查相应布局与菜单状态。
11. **降级回归（R-I）**：禁用 JavaScript 硬刷新验证 `no-js` 常显；禁用 CSS 验证阅读顺序；恢复后确认回到基线。
12. **内容运行时一致性（R-J）**：抽查四页浏览器所见文本与 Task 10 结论一致，段落数量与顺序正确。
13. **汇总回归报告**：按断言编号输出通过／失败清单；每条失败附页面、复现宽度或状态、操作步骤、期望 vs 实际、应移交任务。
14. **确认只读未变**：回归结束后重新计算六个文件 SHA-256 与清单，确认与步骤 2 一致；确认截图、脚本、记录都在 `Results/` 之外。
15. **闸门判定**：全部断言通过时判定整站可交付；存在失败时输出回流清单，不签署通过。

## 回归报告格式

回归结论应可追溯，建议每条一行，至少包含：

```text
[断言编号] [PASS|FAIL] 页面 — 宽度/状态 — 操作步骤 — 期望 vs 实际（失败时） — 移交任务（失败时）
```

- 关键状态（菜单三态、跨断点、200% 缩放）建议附截图，截图保存在 `Results/` 之外。
- 几何测量可记录浏览器子像素舍入，但横向溢出判定严格使用 `scrollWidth <= innerWidth`，不放宽。
- 报告与截图是临时 QA 产物，不得写入六个交付文件，也不得作为额外文件留在 `Results/`。

## 异常处理

- **页面无法打开或资源 404**：停止后续交互回归，移交 Task 2（引用路径）或对应资源任务修复，再重跑。
- **加载阶段控制台报错**：移交 Task 9（脚本）或 Task 3／Task 8（样式解析）；不得用 `try/catch` 吞错制造 0 报错。
- **横向溢出**：定位溢出元素与所在宽度，移交 Task 8（移动）或 Task 3（桌面）；不得用 `overflow-x:hidden` 掩盖。
- **菜单显示了但样式错乱／未折叠**：移交 Task 8 的显示规则。
- **`aria-expanded` 与 `.is-open` 脱节、跨断点未重置、Enter／Space 双触发**：移交 Task 9。
- **点击区不足 44px**：移交 Task 8。
- **禁用 JS 后导航消失**：通常是 CSS `.no-js`／`.js` 特异性问题，移交 Task 8；确认测试是“先禁用再硬刷新”。
- **浏览器所见文本疑似与合同不符**：回流为 Task 10 失败项复核，不在 Task 11 重新逐字符裁定。
- **200% 缩放后进入移动布局**：属预期，不判失败；按实际 `innerWidth` 复查对应状态即可。
- **运行时需临时改 DOM 观察状态**：仅在开发者工具中进行，绝不保存回文件；结束后硬刷新恢复。

## 常见误判风险

- 用某一页（尤其最长的评论页）通过推断四页都通过，漏测首页或短文章页。
- 把 200% 缩放后进入移动布局误判为断点失败，或用截图放大／CSS `zoom` 冒充真实缩放。
- 横向溢出判定放宽 1px，或只看有无滚动条而不测 `scrollWidth`。
- 只在脚本运行后临时关闭 JS 测降级，DOM 残留 `html.js` 导致误判。
- 把静态结构／文本检查当作 Task 11 职责重复裁定，或反过来用肉眼替代 Task 10 的逐字符断言。
- 用内联样式、运行时改 DOM 保存回文件、或临时 `!important` 来“修好”视觉问题，越权侵入上游所有权。
- 忽略控制台警告，只盯错误；或忽略网络面板的外部请求。
- 忘记回归前后比对六个文件哈希，未发现临时脚本或截图误入 `Results/`。
- 把披露式菜单误当模态，强行把焦点移入菜单或加焦点陷阱，与 Task 9 合同冲突。

## 与上游任务的回流关系

- 视觉／布局失败（版心、溢出、字号、换行、点击区、菜单显示）→ Task 3（桌面）或 Task 8（移动）。
- 状态／交互失败（`aria-expanded` 脱节、跨断点未重置、Enter／Space 双触发、控制台报错、焦点策略）→ Task 9。
- 结构／文本失败（节点数量、逐字符、段落边界、禁止项）→ 回流 Task 10 断言，并移交 Task 2／4／5／6／7。
- 资源／路径失败（404、死链、外部请求）→ Task 2（引用）或对应资源任务。
- 任一上游合同（断点值、稳定 ID／class、脚本接口、段落数组、首页权威文本）发生经批准的变更时，必须先更新对应 Task 文件，再同步更新 Task 10 断言与本任务的验收预期，不得只改交付文件而让验收滞后。
- Task 11 通过且 Task 10 通过，是整站视为可交付的共同前提；两者任一未通过，整站不签署完成。
