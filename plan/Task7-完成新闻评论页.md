# Task 7 完成新闻评论页

## 任务定位

本文件将总方案中的 Task 7 细化为一个可以独立执行、独立验收的工作包。它负责在 Task 2 已建立的 `Results/news-commentary.html` 公共壳中，按照 Task 1 冻结的文本基线加入新闻评论的页面类型、标题、公开署名、29 个正文段落和 1 个末尾日期段。

Task 7 是一次严格受控的单页内容录入工作。它不重新解释 Word 文档，不改写事实、观点、数字、技术术语、标点、空格或段落边界，也不借机修改其他页面、共享样式和导航脚本。Task 1 是文本内容的唯一权威基线，Task 2 是公共 HTML 结构的唯一权威基线；Task 3 只提供本文应复用的文章样式接口。

源文件名中的“新闻评价”只用于定位只读素材。面向读者的栏目名称、导航文字和页面类型必须统一为“新闻评论”，不得把源文件名当作公开名称。

## 目标

- 保留 Task 2 为评论页冻结的文档标题、公共报头、四项导航、当前页状态和本地资源引用。
- 在统一文章结构中显示页面类型“新闻评论”、标题“设备升级了，使用门槛也该降下来”和公开署名“蓝色空间”。
- 将 Task 1 的 `C01`–`C29` 按原顺序一一映射为 29 个直接正文 `<p>`，不拆分、不合并、不增删。
- 将 `closing_date` 映射为正文容器之后的独立 `p.article__date`，不计入 29 个正文段落。
- 原样保留 `86英寸`、`Windows 10`、`.exe`、`UOS`、`USB`、`OPS`、`Linux`、`4K`、`5次`、`3个U盘` 和结尾引语等高风险内容。
- 不为末尾日期补年份，不使用 `<time>` 或 `datetime`，不从 Word 文件时间推断任何公开日期。
- 不为“科大讯飞的产品资料”补链接、脚注、来源说明或外部资料。
- 使页面在禁用 CSS 或 JavaScript 时仍按页面类型、标题、署名、29 段正文、末尾日期的顺序完整可读。
- 为 Task 8、Task 10 和 Task 11 提供固定的 DOM 数量、顺序、选择器和逐字符核验合同。

## 字符与段落保真规则

### 1. 通用规则

- `title`、`byline`、`C01`–`C29` 和 `closing_date` 必须与上方合同逐字符相等。
- 不执行 `trim()`、连续空白合并、全半角转换、Unicode 标准化、智能标点替换或自动纠错后再写回页面。
- 每个 `C` 段落完整放入一个 `.article__body > p`；不得把一句拆成多段，也不得把多个段落合并。
- 29 个段落中即使有很短的 C03、C13、C17、C19、C22、C24、C25，也仍是普通正文段落。
- 保留所有中文句号、逗号、顿号、冒号、分号、问号、引号和原有语序。

- 不添加 `<br>`、`&nbsp;`、软连字符、`<wbr>` 或纯为排版而存在的字符。

- 不给正文自动补段落编号、事实来源、脚注、链接、年份、引语出处或结束标记。

- 正文 `<p>` 的开头和结尾不得因源码缩进产生前导或尾随空白。
