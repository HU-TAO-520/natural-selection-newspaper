# Task 6 完成新闻通讯页

## 任务定位

本文件将总方案中的 Task 6 细化为一个可以独立执行、独立验收的工作包。它负责在 Task 2 已建立的 `Results/news-feature.html` 公共壳中，按 Task 1 的冻结文本合同录入新闻通讯的页面类型、标题、署名和 23 个正文段落。

Task 6 只完成新闻通讯页的内容与语义结构，不改写原文，不重建公共壳，不编写视觉样式、响应式规则或导航脚本。完成后，页面应能由 Task 3 的共享文章样式直接排版，并能由 Task 10 按段落数组和 DOM 结构进行字符级核验。

## 目标

- 保留 Task 2 规定的 `news-feature.html` 文档级结构、公共报头、主导航和资源引用。
- 页面类型准确显示为“新闻通讯”，文章标题准确显示为“从数学题到AI时代的学习”。
- 署名只显示“蓝色空间”，不添加“作者：”“记者：”等前缀。
- 将 Task 1 的 `F01`–`F23` 按原顺序一一映射为 23 个正文 `<p>`。
- 省略 Word 文档末尾没有可见字符的空段，不在 HTML 中生成空 `<p>`。
- 原样保留人称不一致、全部标点、引号层级、双破折号、半角空格和 `AI` 大小写。
- 让页面在禁用 CSS 或 JavaScript 时仍按栏目类型、标题、署名、正文的顺序完整可读。

## 文本保真合同

### 通用规则

- 23 个正文段落的顺序和边界完全固定；不得拆段、并段或重排。
- 比较以 DOM `textContent` 为准，并采用逐字符相等；不得先 `trim()`、折叠空白、统一标点或做 Unicode 标准化再判定通过。
- 不纠错、不润色、不调整语序，不补充采访时间、采访地点、受访者身份或资料来源。
- 不把任何短段落改成小标题、列表项、题记、导语或图注。
- 不把段内引语改成 `<blockquote>`、独立 `<p>` 或额外的 `<q>`；中文引号本身就是原文的一部分。
- 除 F01 的电头 `<strong class="dateline">` 外，F02–F23 的正文 `<p>` 只包含文本节点，不插入强调、链接、换行或装饰标签。
- 不在正文前写全角空格制造首行缩进；首行缩进由 `styles.css` 负责。
- 不增加末尾日期段、来源段、作者简介、脚注、注释或相关文章。

### 高风险字符与原样保留项

- F01 的电头精确为 `自然选择号9月17日电`，其后恰好一个 U+0020 半角空格；这也是 23 个正文段落中唯一的 U+0020。
- `9月17日` 不补年份，不转换为带推断年份的 `<time datetime>`。
- F04 的外层中文双引号 `“”` 和内层中文单引号 `‘下限’`、`‘上限’` 必须保持原样。
- 人称必须按段保留：F02 为“他认为”，F05 为“在她看来”，F10 为“仍由他自己完成”，F12 为“不过，他并不赞成”，F20 为“他举了一个简单的例子”；不能双向统一。
- F09 的双破折号必须保持为连续两个 U+2014 字符 `——`，不能替换为连字符、短横线或单个破折号。
- 标题及正文中的 `AI` 全部保持半角大写，不能改成 `Ai`、`ai`、“人工智能”或全角字母；正文中恰有 19 次，连同标题共 20 次。
- F14 的问号、F15 的冒号与引号、F17 的引语句号、F18 的引号均属于原文，不得因 HTML 排版重新组合。
- 所有中文逗号、句号、分号、冒号和问号均按 Task 1 保留，不执行全半角替换。

作为字符级强化检查，23 个正文段落合并后的原始 `textContent` 应包含：`AI` 19 次且 `ai`、`Ai`、`aI` 均为 0，中文左、右双引号各 8 个，中文左、右单引号各 2 个，U+2014 共 2 个且相邻组成唯一一处 `——`，全角问号 1 个、全角冒号 2 个、中文分号 3 个、U+0020 共 1 个。该计数只用于发现录入漂移，不能替代逐段严格比较。

## 异常处理

- **源文件哈希变化**：停止录入，保存新旧哈希并回到 Task 1；未经确认不得继续使用旧数组。
- **Task 2 页面不存在**：先执行 Task 2，不由 Task 6 独立重建公共壳。
- **公共壳与 Task 2 不一致**：区分用户后续批准的变更与意外漂移；先更新或修复 Task 2 合同，再继续正文录入。
- **目标页已有正文**：先逐项比较结构和 `textContent`；只保留与本合同完全一致的部分，不整页覆盖用户的无关修改。
- **标题或署名不同**：以已核验的 Task 1 为内容权威，停止并查明来源；不能保留两个版本或增加副标题解释。
- **段落数量不是 23**：检查是否误把标题、署名、尾部空段计入正文，或是否拆分了段内引语；不得为凑数合并或删除文本。
- **浏览器文本比较多出空白**：检查 F01 内联标签前后的源码换行及各 `<p>` 内部缩进，不用 `trim()` 掩盖问题。
- **发现疑似错字或人称问题**：原样保留并记录；只有用户明确提供修订文本且 Task 1 同步更新后才能改变。
- **样式需要额外包装**：优先使用 Task 3 已定义的 `.article*` 接口；不得仅为视觉效果拆段或插入空元素。
- **长英文在窄屏溢出**：交给 Task 8 的共享 CSS 处理，不在正文中插入软连字符、零宽字符或额外空格。
