# Task 5 完成新闻消息页

## 任务定位

本文件将总方案中的 Task 5 细化为一个可以独立执行、独立验收的工作包。它负责在 Task 2 已建立的 `Results/news-message.html` 公共壳中加入新闻类型、标题、公开署名和 Task 1 冻结的 4 个正文段落，最终形成完整的新闻消息页。

Task 5 是一次严格受控的单页内容录入工作。它不得重新解释 Word 文档，不得修改新闻事实、数字、标点、空格或段落边界，也不得借机调整其他页面、共享样式或导航脚本。Task 1 是文本的唯一权威基线，Task 2 是页面公共结构的唯一权威基线。

## 目标

- 保留 Task 2 已冻结的消息页文档标题、公共壳、四项导航和当前页状态。
- 将页面类型“新闻消息”、标题“我校启动校本课程志愿填报”和公开署名“蓝色空间”放入稳定的文章语义结构。
- 将 Task 1 的 `M01`–`M04` 一一映射为 4 个直接正文段落，不拆分、不合并、不增删。
- 只对 M01 的电头使用允许的内联强调标记，并确保电头后的 U+0020 半角空格仍属于正文文本。
- 使页面在没有 CSS 或 JavaScript 时仍按正确顺序完整可读。
- 为 Task 8、Task 10 和 Task 11 提供固定的 DOM 数量、顺序、选择器和逐字符验收基线。

## 前置条件与后续依赖

- 内容前置条件：Task 1 已完成，`Materials/新闻消息.docx` 的 SHA-256、标题、署名和 `M01`–`M04` 已冻结。
- 结构前置条件：Task 2 已完成，`Results/news-message.html` 已存在并符合公共 HTML 壳、页面登记表和导航矩阵。
- 样式协作：Task 3 可以在 Task 2 后并行建立 `.article*` 与 `.dateline` 的共享样式，但不得与本任务同时无协调地编辑 `Results/news-message.html`。
- 直接依赖本任务的工作：Task 8 移动端内容适配、Task 10 结构与文本自动核验、Task 11 浏览器回归。
- 阻断规则一：源文件当前 SHA-256 与 Task 1 不一致时，停止使用本文件中的旧文本合同，返回 Task 1 重新确认素材版本。
- 阻断规则二：消息页不存在、公共壳不完整或页面标题与 Task 2 不一致时，暂停 Task 5 并移交 Task 2 处理；Task 5 本身不修改上游计划、其他页面或共享壳接口。

## 字符与段落保真规则

### 1. 通用规则

- `title`、`byline`、`M01`–`M04` 必须与上方合同逐字符相等。
- 不执行 `trim()`、连续空白合并、全半角转换、Unicode 标准化、智能标点替换或自动纠错后再写回页面。
- 每个 `M` 段落完整放入一个 `<p>`；不得把一句拆成多段，也不得把多个段落合并。
- 保留所有中文句号、逗号、顿号、分号和原有语序。
- 不为短段落增加小标题，不把列举内容改成列表，不把任何句子改成引用块。
- 不添加 `<br>`、`&nbsp;`、软连字符、`<wbr>` 或纯为排版而存在的字符。
- HTML 源码若需要实体转义，浏览器 DOM 的 `textContent` 仍必须与合同相等。
- 不给正文自动补书名号、引号、段落编号、日期、来源或结束标记。

### 2. 高风险字符串

以下字符串必须原样存在，可作为快速诊断点，但不能代替全文比较：

- `自然选择号9月18日7时电`
- `今日7时`
- `第一志愿、第二志愿`
- `47个社团`
- M02 中“进行录取；部分社团”的中文分号 `；`
- `目前，校本课程志愿填报工作正在进行中。`

不得把 `今日7时` 改成具体日期，不得在 `9月18日` 前补年份，也不得把 `47个社团` 改成带空格或阿拉伯数字全角形式。

### 3. 电头边界

M01 的电头是：

```text
自然选择号9月18日7时电
```

允许且推荐使用 `<strong class="dateline">` 包裹该电头，但必须满足：

- `<strong>` 只包裹从“自”到“电”的 13 个可见字符，不包含后面的空格或正文。
- `<strong>` 结束标签后紧接一个 U+0020 半角空格，再接“我校校本课程……”。
- 该空格来自 HTML 正文，不由 CSS 的 `margin`、伪元素 `content` 或 JavaScript 生成。
- `<p>` 开始标签与 `<strong>` 之间没有可见前导空格。
- 半角空格不能改为 `&nbsp;`、全角空格、换行缩进或多个连续空格。
- M01 的整个段落 `textContent` 必须仍与 Task 1 的 M01 完全相等。

为避免源码格式化给文本节点引入换行和缩进，M01 应写在同一源代码行：

```html
<p><strong class="dateline">自然选择号9月18日7时电</strong> 我校校本课程志愿填报于今日7时正式启动。……</p>
```

省略号只用于本计划的边界示例，不得进入最终页面；完整权威段落见下方 HTML 合同。

## 内容到 DOM 的映射

| 内容角色 | HTML 元素 | Class | 数量 | 文本来源 |
| --- | --- | --- | --- | --- |
| 文章整体 | `<article>` | `.article` | 1 | 不承载额外可见文本 |
| 文章头部 | `<header>` | `.article__header` | 1 | 包含类型、标题、署名 |
| 页面类型 | `<p>` | `.article__type` | 1 | 固定为“新闻消息” |
| 文章标题 | `<h1>` | `.page-title` | 1 | Task 1 `title`／Task 2 `<h1>` |
| 公开署名 | `<p>` | `.article__byline` | 1 | Task 1 `byline` |
| 正文容器 | `<div>` | `.article__body` | 1 | 只容纳 4 个正文段落 |
| 正文段落 | `<p>` | 无需单独 class | 4 | 依次为 M01、M02、M03、M04 |
| 电头强调 | `<strong>` | `.dateline` | 1 | M01 开头电头 |

`.article__header` 的直接元素子节点顺序固定为 `.article__type`、`h1.page-title`、`.article__byline`。`.article__body` 紧随文章头部，并且其直接元素子节点恰好是 4 个 `<p>`。

消息页没有独立末尾日期段，因此不得加入 `.article__date`。文章页也不需要第二个标题、摘要、导语标签、作者简介、关键词或来源区。

## 权威 `#main-content` HTML 合同

Task 5 完成后，`#main-content` 内部结构和文字必须与下列模板一致：

```html
<main class="main-content" id="main-content" tabindex="-1">
  <article class="article">
    <header class="article__header">
      <p class="article__type">新闻消息</p>
      <h1 class="page-title">我校启动校本课程志愿填报</h1>
      <p class="article__byline">蓝色空间</p>
    </header>

    <div class="article__body">
      <p><strong class="dateline">自然选择号9月18日7时电</strong> 我校校本课程志愿填报于今日7时正式启动。本次志愿填报采用第一志愿、第二志愿的方式，共有47个社团供学生选择。若两项志愿均未被录取，学生将被调剂至尚有名额的其他社团。</p>
      <p>据了解，本次校本课程录取主要分为志愿填报和定向招生两种方式。普通志愿按照学校公布的规则进行录取；部分社团则有特定的招生要求。例如，心理社团面向心理委员招生，合唱团报名者需要向指导老师展示一段演唱，经老师同意后方可加入。</p>
      <p>在此前的动员会上，老师也提醒同学们，即使最终没有进入最初希望选择的社团，也可以尝试了解调剂后的课程，在新的活动中获得不同的体验。</p>
      <p>目前，校本课程志愿填报工作正在进行中。</p>
    </div>
  </article>
</main>
```

该模板是 Task 5 所有正文区域的权威版本。页面中 `<main>` 之前的 `<head>`、跳至正文链接、报头、菜单按钮和导航继续以 Task 2 为准，不得用此片段重建或替换公共壳。

源代码为了可读性产生的 article、header、div 之间空白文本节点不属于可见文章内容；4 个正文 `<p>` 内不得因为换行排版产生额外文本空白。

## 语义与无障碍合同

- 页面继续只有一个 `<main>` 和一个 `<h1>`。
- `<article>` 表示一篇可独立理解的新闻文章，并且是 `#main-content` 唯一的直接元素子节点。
- 文章头部使用 `<header>`，但不得添加第二个站点级 `<header>` 选择器假设；站点报头仍是 Task 2 的 `.site-header`。
- 页面类型和署名都是普通段落，不使用额外标题级别，避免把栏目名或作者变成文档大纲节点。
- 标题继续使用 Task 2 已存在的 `.page-title`；不得创建 `.article-title` 取代它。
- 署名只显示“蓝色空间”，不添加“作者：”“记者：”“文／”或隐藏的替代名称。
- 不给文章添加重复的 `aria-label`，可见 `<h1>` 已提供清晰名称。
- 不使用 `role="article"`、`role="document"` 等冗余角色。
- 不把静态正文放入 `<section>`、`<aside>`、`<details>`、列表或交互组件。
- 不使用 `<time>` 或 `datetime` 表示 M01 内的月日和时刻，因为原文没有可安全推断的年份。
- 禁用 CSS 与 JavaScript 后，阅读顺序仍必须是页面类型、标题、署名、M01、M02、M03、M04。

## 子任务拆分

### Task 5.1 校验素材版本与实施输入

输入：`Materials/新闻消息.docx`、Task 1 冻结哈希与权威文本合同。

执行：

2. 与冻结值完整比较。
3. 确认实施输入只包含 `type`、`title`、`byline`、`M01`–`M04`。
4. 确认没有从文件属性、样式名或创建时间生成额外字段。

输出：一个通过版本门禁的只读内容输入集。

完成条件：哈希匹配，7 个公开文本字段及其角色明确；若不匹配，本任务停止在此，不改消息页。

### Task 5.2 回归检查 Task 2 消息页公共壳

输入：`Results/news-message.html`、Task 2 页面登记表和公共结构合同。

执行：

1. 确认文件存在且可读取。
2. 检查 `<title>`、唯一 `<h1>`、`#main-content` 和共享资源引用。
3. 检查跳至正文链接、报头、按钮、导航 ID 和初始 ARIA 状态。
4. 检查四个导航链接的文字、顺序、目标以及消息页唯一当前项。
5. 记录修改前的目标页状态，避免覆盖用户新增的非冲突改动。

输出：通过 Task 2 回归的可编辑消息页。

完成条件：公共壳全部符合合同；任何结构漂移先按异常处理，不进入正文录入。

### Task 5.3 建立文章语义容器

输入：Task 2 中仅含 `.page-title` 的 `#main-content`。

执行：

1. 在 `#main-content` 中创建唯一 `.article`。
2. 创建唯一 `.article__header` 和 `.article__body`。
3. 把既有 `h1.page-title` 移入 `.article__header`，保持文本与 class 不变。
4. 确保 `<main>`、`#main-content`、`tabindex="-1"` 和唯一标题数量不变。

输出：可承载文章元信息与正文的稳定 DOM 骨架。

完成条件：`main > article`、`article > header + div` 的直接子级关系成立，页面仍恰好有一个 `<h1>`。

### Task 5.4 录入类型、标题与公开署名

输入：`type`、`title`、`byline`。

执行：

1. 在标题前加入 `<p class="article__type">新闻消息</p>`。
2. 保留 `<h1 class="page-title">我校启动校本课程志愿填报</h1>`。
3. 在标题后加入 `<p class="article__byline">蓝色空间</p>`。
4. 核对三项的直接子级顺序和逐字符文本。

输出：内容完整的文章头部。

完成条件：文章头部恰好有 3 个直接元素子节点，没有作者前缀、日期、摘要或其他文本。

### Task 5.5 录入四个正文段落与电头标记

输入：Task 1 的 `M01`–`M04`。

执行：

## 异常处理

- **源文件哈希变化**：停止 Task 5，不使用旧数组继续录入；记录新旧哈希，回到 Task 1 确认是否为用户批准的新版本。
- **消息页尚不存在**：先执行 Task 2；不得让 Task 5 独立手写一套可能漂移的完整页面壳。
- **公共壳与 Task 2 不一致**：区分用户批准的后续修改和意外漂移。若修改改变了公共 ID、导航拓扑、标题或当前项，暂停 Task 5 并移交 Task 2 处理；Task 5 不直接修改上游合同或范围外页面。
- **页面已含文章内容**：先按本合同逐项比较。完全一致的节点可保留；冲突内容不得简单叠加。保留不冲突的用户改动，并把未获授权的内容差异报告出来。
- **已有多个 `<h1>`**：停止录入并修复结构，只保留 Task 2 标题；不得通过 CSS 隐藏重复标题。
- **电头格式化后出现多余空格**：把 M01 的 `<p>` 写回单行，检查 `strong` 后的实际文本节点；不得用 CSS 负间距掩盖字符错误。
- **HTML 格式化器重排正文**：以 DOM `textContent` 为准检查是否引入换行或空格；必要时对四个正文 `<p>` 保持单行源码。
- **样式接口尚未实现**：保留正确 class 和语义结构，交由 Task 3；不在消息页添加专属 CSS。
- **出现补年份或作者的建议**：视为超出当前授权的新内容变更，未获明确确认前不实施。
- **自动核验与视觉阅读不一致**：先检查实体解码、文本节点、换行和内联标签边界，不凭肉眼相似判定通过。
- **并发编辑冲突**：停止覆盖，比较当前文件与修改前状态，合并不冲突的用户变更后重新执行全部核验。
