## 公共壳合同

### 1. 槽位定义

`build/shell.html` 的字面结构（不含 `{{...}}` 以外的任何变量）：

```html
<!doctype html>
…（基线 news-message.html 第 1 行至 <main> 开标签行，逐字节，只含 §2 所列两处编辑：标题主体改 {{TITLE}}、删去基线 :36 的 aria-current）…
  <main class="main-content" id="main-content" tabindex="-1">
{{MAIN}}
  </main>
</body>
</html>
```

替换规则（唯一、确定性、无正则魔法）：

1. `{{TITLE}}` → 页面标题主体；`<title>` 行的完整形态固定为 `  <title>{{TITLE}}｜自然选择号</title>`，全角 `｜` 后缀属于壳、不可变。
2. `{{MAIN}}\n` 整串（含其后的那一个 LF）→ `<main>` 内部字节序列（以 `\n` 结尾）。**只允许这一处替换规则**，不得出现"如果内容为空就不换"之类分支。
3. 当前项高亮**不是壳里的既有文本**，而是构建器的一次定位替换：壳是 `Results/news-message.html` 的字节副本，里面没有 `{currentHref}` 这种占位符，因此模式按字面量定义——`href="` + 当前输出文件名 + `"`（例如首页为 `href="index.html"`，详情页为 `href="news-message.html"`）。构建器的定位方式是：先取出 `  <nav class="site-navigation" id="site-navigation" aria-label="主导航">` 到其配对 `</nav>` 之间的子树文本（作用域即 `#site-navigation`），在其中数该字面量的出现次数——**必须恰好一次**，命中 0 次或多于 1 次一律退出码 2；然后把命中的那一处替换为 `href="…"` ＋ ` aria-current="page"`（属性顺序与基线 `Results/news-message.html:36` 逐字一致，中间恰一个 ASCII 空格）。子树之外（含 `.site-masthead`）出现的同名 href 一律不是候选，因此首页 `href="index.html"` 在整份壳里有两处（报头 `:16` ＋ 导航 `:33`）也仍然只命中一处，"多于 1 次即退出"这条判据只对 nav 子树内部成立。
4. 报头链接（`href="index.html"` 出现在 `.site-masthead` 内那一处）**永不**获得 `aria-current`；`index.html` 的当前项必须落在 `.site-navigation__list` 内的那个首页链接上。构建器对"nav 子树外命中"与"nav 子树内非唯一命中"两种情形都以退出码 2 报错，不得用"只替换首次出现"来绕过重复计数——该做法会让首页在报头与导航之间二义地落点。

### 2. Markdown 子集渲染（约 60 行，手写）

处理链固定为五步，任何一步失败即退出码 2：

1. **字节归一**：拒绝 BOM、拒绝 CRLF 与孤立 CR、拒绝 TAB、拒绝行尾空白、拒绝无末尾 LF；其余字符一律原样（**不做** Unicode 归一化、不折叠全半角、不替换 `“”‘’——`）。
2. **切块**：正文区按连续空行切分为块；块数 ≥ 1。
3. **单行校验**：每一块必须只含一行——块内出现 LF 即报错（`Task13 §正文区规则 1`）。这是在段落中间静默丢空格的唯一入口，必须结构性堵死。
4. **标记校验**：块文本中允许出现的 Markdown 记号只有"第一块行首的 `**…**`"一对；其余任何 `*`、`` ` ``、`<`、`>`、`#`、`[`、`]`、`!`，以及行首的 `-`、`*`、`>`、`|`、`~`、`\d+\.` 一律报错。
5. **段落装配**：第一块若以 `**` 起、以 `**` 止于某处，则该段输出 `        <p><strong class="dateline">电头</strong> 其余文本</p>`；电头闭合 `**` 之后必须紧跟**恰好一个 U+0020**，否则报错（`Task1 §4` 的高风险点）。其余段输出 `        <p>文本</p>`。

转义规则：对文本节点只替换 `&`→`&amp;`、`<`→`&lt;`、`>`→`&gt;`，**不替换引号**（文本节点里的引号无需转义，且当前素材含大量全角引号，替换引号会污染输出）。由于第 4 步已禁止 `< > &` 出现在内容源中，三篇迁移文的转义结果必须与输入逐字符相等——这本身是一条断言。

### 3. 三种页面的装配

**文章详情页**（`article-<slug>.html`）`<main>` 内部：

```html
    <article class="article">
      <header class="article__header">
        <p class="article__type">{栏目名}</p>
        <h1 class="page-title">{title}</h1>
        <p class="article__byline">{byline}</p>
      </header>

      <div class="article__body">
{每段一行，段间不空行}
      </div>

      <p class="article__date">{end_date}</p>
    </article>
```

缩进为 4／6／8 空格（实测基线三页完全一致）。`<p class="article__date">` 一行**仅在 `end_date` 存在时输出**，其前恰有一个空行、位于 `.article__body` 之后、`</article>` 之前。`<title>` 主体 = `title`；`currentHref` = 该文章 `column` 在 `content/columns.md` 里对应那一行的**第三列原值**（`message` → `news-message.html`、`feature` → `news-feature.html`、`commentary` → `news-commentary.html`），逐字复制注册表第三列，**不得再加 `news-` 前缀**（那会拼出 `news-news-message.html` 这种不存在的 href，§1 第 3 条的字面量匹配必然命中 0 次并以退出码 2 失败）。

**栏目列表页**（`news-message.html` 等）：

```html
    <h1 class="page-title">{栏目名}</h1>

    <ul class="entry-list">
      <li class="entry-list__item">
        <a class="entry-list__link" href="article-{slug}.html"><span class="entry-list__title">{title}</span><span class="entry-list__date">{display_date}</span></a>
      </li>
    </ul>
```

`<span class="entry-list__date">` 仅在该文章有 `display_date` 时输出；同栏目全部无日期时，`<ul>` 内不得残留任何空行或占位。`<title>` 主体 = 栏目名，`currentHref` = 自身文件名。

**首页**：`<h1 class="page-title">《自然选择号》报社简介</h1>`（逐字来自基线）+ 空行 + `build/partials/home-intro.html` + 空行 + 生成的最新区：

```html
      <ul class="home-latest__list">

          <a class="home-latest__link" href="article-{slug}.html"><span class="home-latest__entry">{title}</span><span class="home-latest__date">{display_date}</span></a>
        </li>
      </ul>

```

取**全局排序后的前 3 条**（R11①：不是"每栏目一条"），次序即 R11 四键全序；当前三篇按该序输出为 消息 → 通讯 → 评论，与 `Task12` R4 白名单第 9–14 项逐字一致。内容源不足 3 篇或多于 3 篇时**停止并回流 `Task12` 修订 R4**，构建器不得自行降级、补齐或截断。`currentHref` = `index.html`。

## 异常处理

- **S1 不等**：三选一排查——渲染器改了字符（标点替换、空白折叠）、基线切片取错边界、`content/` 与 `Task1` 不一致。定位前不得放宽 S1，也不得"以渲染结果为准"回改 `content/`。
- **壳回切失败**：说明槽位定义或 `aria-current` 插入与基线不一致；回到 14.2 重切，不接受"三页过一页不过"。
- **两次构建不等**：几乎必然是顺序或时间来源问题（`readdir` 顺序、`dict` 迭代序、`datetime.now()`、`hashlib` 输入包含 mtime）。移除不确定性来源，而不是给哈希加归一化。
- **`--check` 报漂移但人看不出差别**：先查行尾（CRLF 被编辑器改写）、BOM、末尾换行、Tab 展开；用码点对比而不是肉眼看 diff。
- **`content/` 被本包意外写**：立即停止，重算其哈希并与 Task 13 报告比对，恢复由 Task 13 侧执行；本包不"顺手改回去"以图省事。
- **发现 `Task13` 允许面与 `Task12` 字段表不一致**：回流上游澄清（例如某键必填性、某标记是否允许），不得在构建器里实现两套。
- **素材将来需要更富结构**（列表、图片、链接）：属于新需求，须先由用户批准并回 Task 12/13 扩合同；本包不为假想需求预先支持语法。
- **文章数量增长导致列表页很长**：本轮不做分页，也不得临时生成"折叠""显示更多"这类合同外交互。
- **Python 版本差异**：只用 3.9+ 稳定语法与标准库；不使用实验特性；报告里记录实际运行版本，但不把版本写进产物文件。

## 常见返工风险

- 在本包写一份"临时渲染器"来看效果，事后与正式版漂移——这正是 `Task13` 的"对 Task 12 §后续任务交接（给 Task 13）的口径澄清"一节要避免的双份真相（该节引用的是 Task 12 的交接条；Task 12 只有 12.1–12.9，不存在"13.5"一节）。
- 用正则一把梭地"提取 front-matter"，导致正文里的 `---` 或 `:` 被误解释。
- 让解析器"宽容"处理未知键或多余空格，把内容源的语法错误推迟成输出错误。
- 折叠段落内连续空格、`strip()` 段落文本、或对 CJK 标点做智能替换，任何一条都会静默改变正文字符。
- 把 `<p>` 写成多行缩进（模板换行），使 `textContent` 出现额外空白而页面看起来仍然正常。
- 转义引号：`“”` 被替换成 `&quot;` 或被规范化为直引号，破坏 `Task1` 码点合同。
- 电头分支写成"任何位置出现 `**` 都转 strong"，于是未来的行内强调静默变成电头样式。
- `aria-current` 用模板全量重写 nav 块，导致属性顺序或空格与基线不同，撞穿 C／D／K 组。
- 排序引入 `datetime.strptime` 或 locale 设置，换机换序；ISO 字符串本身即可字典序比较。
- 用 `dict` 插入顺序输出页面，或依赖 `Path.iterdir()` 的返回顺序，导致两次构建字节相同但顺序不同（进而哈希链断裂）。
- 先写盘再自检：一旦中途失败，部署根里就留下半套页面。必须"全有或全无"。
- 忘记写后读回复比，于是编码转换或换行改写被静默接受。
- 把 `__pycache__`、`.orig`、临时 diff 文件留在输出目录，并被 Task 17 用目录通配打包进去。
- 生成"暂无文章""日期未知"之类占位文案，令 R5④ 与"不生成未注册文本"同时失效。
- 首页引言块由渲染器重新拼装（而不是逐字节 partial），使 `E6` 的逐字符合同依赖渲染器正确性。
